# Domain Modeling

This domain teaches how to model business complexity so software reflects real
organizational language, decisions, and constraints instead of just technical structure.
It centers on Domain-Driven Design across both strategic design (subdomains, bounded
contexts, context maps) and tactical design (aggregates, entities, value objects,
repositories, and domain events).

Concept IDs are subject-scoped (e.g. `ddd-evans/07`), so this `domain-modeling/` folder organizes files on disk without changing how you refer to a concept.

## Subjects

| Subject | What it is | Lessons | Index |
| --- | --- | --- | --- |
| **DDD Evans** | *Domain-Driven Design: Tackling Complexity in the Heart of Software* (Eric Evans) - the original DDD foundation, defining strategic and tactical modeling language. | 16 | [ddd-evans/README.md](ddd-evans/README.md) |
| **Implementing DDD** | *Implementing Domain-Driven Design* (Vaughn Vernon) - deep practical guidance for aggregates, bounded contexts, events, and integration. | 15 | [implementing-ddd/README.md](implementing-ddd/README.md) |
| **Learning DDD** | *Learning Domain-Driven Design* (Vlad Khononov) - a modern, accessible path that starts from strategic design and links it to implementation. | 14 | [learning-ddd/README.md](learning-ddd/README.md) |
| **DDD Distilled** | *Domain-Driven Design Distilled* (Vaughn Vernon) - a concise primer of core DDD ideas and adoption patterns. | 9 | [ddd-distilled/README.md](ddd-distilled/README.md) |

A sensible path is to start with DDD Distilled for a quick map, then study DDD Evans
for foundations, use Learning DDD to modernize the framing, and finish with
Implementing DDD for deeper execution details.

See each subject's `README.md` for its concept index and progress, and the root
[SUMMARY.md](../SUMMARY.md) for the cross-domain overview.
