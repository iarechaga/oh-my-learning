# Domain-Driven Design: Tackling Complexity in the Heart of Software

This subject is the original DDD foundation - the blue-book mental model for turning
messy business knowledge into software models that can survive real change. It covers
both tactical modeling patterns and strategic design choices, with strong emphasis on
language, model integrity, and where complexity should live.

**Source book:** *Domain-Driven Design: Tackling Complexity in the Heart of Software* - Eric Evans (Addison-Wesley, 2003).

**Seniority baseline:** senior (lessons range mid->staff).

**How to use this subject:** read a lesson on your own, then ask to *discuss
`ddd-evans/<NN>`* (e.g. *"discuss `ddd-evans/03`"*). Ordered by dependency: shared language and model intent first, tactical building blocks next, then strategic boundaries and system evolution.
