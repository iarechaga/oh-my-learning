# Building Evolutionary Architectures

The change-over-time layer of the track: how to build architectures that can evolve
safely as requirements shift, using **fitness functions** to protect important
architectural characteristics as first-class, automatable guardrails. Covers
incremental change, appropriate coupling, data evolution, and governing evolution at
scale. Cross-links to Fundamentals (characteristics) and The Hard Parts (coupling).

**Source book:** *Building Evolutionary Architectures* (2nd edition) - Neal Ford,
Rebecca Parsons, Patrick Kua, and Pramod Sadalage (O'Reilly, 2022).

**How to use this subject:** read a lesson on your own, then ask to *discuss
`evolutionary-architectures/<NN>`* (e.g. *"discuss `evolutionary-architectures/02`"*).
Ordered by dependency: the definition and fitness functions first, then incremental
change and coupling, then data and pitfalls, then governance.

**Seniority baseline:** staff (lessons range senior->staff).
