# Clean Code

The readability layer of the software-engineering track: how to write code that humans
can read and change with confidence - meaningful names, small honest functions,
comments that earn their place, disciplined formatting, and the code smells that signal
trouble. The narrowest and most immediately applicable subject; it pairs with Code
Complete (construction) and feeds Refactoring (fixing what smells).

**Source book:** *Clean Code: A Handbook of Agile Software Craftsmanship* - Robert C.
Martin (Prentice Hall, 2008).

**How to use this subject:** read a lesson on your own, then ask to *discuss
`clean-code/<NN>`* (e.g. *"discuss `clean-code/03`"*). Ordered by dependency: what clean
code is, then the building blocks (names, functions, comments), then structure, error
handling, boundaries, and smells.

**Seniority baseline:** junior-mid (lessons range junior->senior).
